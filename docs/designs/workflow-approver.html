Workflow Approver

      What each control calls

      Endpoints are live on /v1/workflow/. Counts on this screen come from one resolve call, never from client-side arithmetic.

      ControlRequestNotes
      Rail list, counts GET /approver-groups/ Needs workflow.group.view. Tenant comes from the asserted ?tenant=.
      Member list, “resolves to N”, effective approvers GET /approver-groups/{id}/resolve/ Runs the engine’s own resolution, so the screen cannot disagree with an activation. ?branch= previews branch narrowing.
      Add member (person, role, or position) POST /approver-groups/{id}/members/ {kind, user | role_key | position_code}. Re-adding returns 200, not a duplicate.
      Remove member DELETE /approver-groups/{id}/members/{member_id}/ Scoped to the group, so a member id from another tenant cannot be guessed.
      New group POST /approver-groups/ Code is immutable once created because published templates reference it.
      Delete group DELETE /approver-groups/{id}/ Returns 409 APPROVER_GROUP_IN_USE while a live step routes to it. Deactivate instead.
